# Changelog

## v2.3.1 — 2026-07-15

**Fixed**
- Architecture diagrams are now visible in tool responses: the generated
  README was wrapped in a code fence, which broke the Mermaid blocks inside
  it. Responses now return the README as raw markdown.
- File batches in the no-key job flow use 4-backtick fences, so source files
  containing ``` can no longer break a batch.

**Changed**
- Reports note where Mermaid diagrams render (GitHub / IDE previews).
- Dependency guard: `mcp>=1.10,<2` protects installs from a future breaking
  major release of the MCP SDK.

## v2.3.0 — 2026-07-14

**Added**
- **No-API-key mode for every MCP app** (Claude Code, Cursor, Codex,
  Antigravity, ...): the new `start_doc_job` → `get_next_files` →
  `submit_docs` → `finish_doc_job` flow lets your AI app's own model write
  the docs while the server handles cloning, batching, diagrams, and
  delivery.
- Clear, actionable error when an app doesn't support MCP sampling (was a
  raw "Method not found").

## v2.2.0 — 2026-07-14 (first public release)

- **MCP server + CLI** documenting GitHub repos and local projects with any
  LLM (Anthropic, OpenAI, Azure, Bedrock, Ollama) or the host's own model.
- **Mermaid architecture diagrams**: project map + module-dependency chart
  generated by static analysis (always valid); model-drawn flow charts
  validated before shipping.
- **Four documentation styles**: `readme`, `api`, `architecture`, `tutorial`.
- **Delivery options**: local folder, inline in chat, or a GitHub pull
  request. Incremental re-runs via content-hash caching.
- **Public-hosting safety**: bring-your-own-key headers, `BYOK_ONLY` mode,
  SSRF + DNS-rebinding guards, request sandboxing, rate limiting, size and
  time limits.
- Streamable HTTP (`/mcp`) + legacy SSE (`/sse`) transports, one-click
  Render deploy, GitHub Action, PyPI package.
