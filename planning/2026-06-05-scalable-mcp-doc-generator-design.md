# Scalable Multi-Provider MCP Documentation Generator — Design

**Date:** 2026-06-05
**Status:** Approved (design); pending implementation plan
**Project:** `ai_document_creator` (AI Document Creator MCP server)
**Live remote:** https://ai-document-creator-agdr.onrender.com/sse (Render, SSE transport)

## 1. Goal & Context

Turn the current single-purpose MCP server (clones a GitHub repo, generates docs with one
hard-coded LLM, optionally pushes back) into a **globally distributable, multi-provider
documentation engine** that works for both **GitHub repositories** and **local projects**,
and that **scales without unbounded cost or reliability risk**.

The current implementation lives in `ai_document_creator/` and consists of a LangGraph
pipeline (`core/graph.py`), a file traverser, a repo loader (clone), a doc writer, a CLI
(`main.py`), and a FastMCP server (`mcp_server_impl.py`) deployed on Render in SSE mode.

### Success criteria
- A developer can add the server to any MCP host (Claude Code, Antigravity, Cursor, Windsurf)
  and document a **local project** with no code upload.
- The same server documents a **GitHub repo** (remote or local).
- Documentation can be generated by **any LLM**: Anthropic, OpenAI, Azure OpenAI, AWS Bedrock,
  Ollama — or by the **host agent's own model** at zero API cost to the operator.
- The system is hardened so that growth to many concurrent users does not cause cost blowups,
  crashes, security incidents, or data loss.

## 2. Core Architecture — Two Axes Over One Pipeline

GitHub-vs-local and your-LLM-vs-their-LLM are **not** separate products. They are two
independent axes over a single, unchanged pipeline:

```
            ┌─────────── one LangGraph pipeline ───────────┐
 source  →  │  traverse → generate per-file → synthesize    │ → write .md
            └───────────────────────────────────────────────┘
 source:   git (clone URL)        | local (read a path, stdio)
 backend:  host LLM (MCP sampling, $0) | provider key (anthropic/openai/azure/bedrock/ollama)
 transport: remote SSE (Render)   | local stdio (uvx / docker)
```

- **Source axis** decides *where files come from*.
- **Backend axis** decides *which LLM writes the text*.
- **Transport axis** decides *how the host reaches the server*.

The pipeline in the middle never changes; only the edges swap.

## 3. Module Architecture

Refactor `ai_document_creator/` into small, single-purpose, independently testable modules:

```
core/
  sources.py      # WHERE files come from. GitSource (clone URL) + LocalSource (read a path).
                  #   Common interface: .root_path, .iter_files() → manifest. FileTraverser reused by both.
                  #   RepoLoader becomes GitSource.
  backends.py     # WHO generates text. CompletionBackend interface with two impls:
                  #   SamplingBackend (host LLM via ctx.sample, $0) and
                  #   ProviderBackend (LangChain init_chat_model: anthropic/openai/azure/bedrock/ollama).
                  #   pick_backend(ctx, config): key set → provider; else host sampling; else clear error.
  graph.py        # LangGraph pipeline, backend-agnostic (NO module-level LLM).
                  #   nodes: analyze → [generate_docs | generate_diagrams] → synthesize_index
  profiles.py     # WHAT to produce. Prompt-template sets per profile: "readme", "api-reference", "onboarding".
  diagrams.py     # Mermaid generation (architecture + dependency graph) as its own node.
  cache.py        # Incremental engine. Reads/writes .docai/manifest.json (path → content hash + profile + model).
                  #   Returns the changed-files subset so only changed files are regenerated.
  doc_writer.py   # Writes .md tree + index; also writes the cache manifest.
  config.py       # Resolves settings from args/env/.docai.yml (provider, profile, ignore globs, limits).

mcp_server_impl.py  # MCP tools (stdio + SSE). Thin — delegates to core.
cli.py              # Shared entrypoint used by both main.py and the GitHub Action.
action.yml          # GitHub Action wrapper (BYOK via repo secrets).
pyproject.toml      # Packaging for `uvx documentation-ai` + MCP registry listing.
```

Two key wins:
- **`sources.py`** makes local-vs-GitHub a one-line swap.
- **`backends.py`** makes host-LLM-vs-any-provider a one-line swap.

## 4. MCP Surface

Tools exposed by the server:

- `document_local_project(path=".", profile="readme", incremental=true, diagrams=true, provider=null)`
  — for Claude Code / Antigravity / Cursor on a local folder (stdio).
- `document_repo(repo_url, profile="readme", incremental=true, diagrams=true, provider=null, push=false)`
  — the existing GitHub path, upgraded with the new options. **Push is PR-based** (opens a pull
  request; never force-pushes to the user's default branch).
- `check_doc_drift(path_or_url)` — reports which files changed since docs were last generated
  (reuses `cache.py`; cheap, no LLM). Designed as a CI hook.

### The host-LLM ($0) path — MCP Sampling
When no provider key is configured, `SamplingBackend` calls `ctx.sample(prompt)` so the
developer's own host model (Claude Code / Antigravity) writes the docs — zero API cost to the
operator. Same pipeline, different backend. If the host does **not** support sampling **and** no
key is set, the tool returns a clear, actionable message ("add a provider key or use a host that
supports sampling"). The **GitHub Action** has no host, so it always uses `ProviderBackend` with
a key from repo secrets.

## 5. The Four v1 Features (each an isolated module)

- **Incremental docs** → `cache.py`. After a run, write `.docai/manifest.json` mapping each
  relative path to `SHA-256(content) + profile + model`. Next run hashes files, regenerates only
  the changed set, reuses the rest from disk. Deterministic; no LLM needed to decide. Also powers
  `check_doc_drift`.
- **Mermaid diagrams** → `diagrams.py`, a parallel graph node. Two diagram types: a
  module/architecture diagram (from file tree + imports) and a dependency diagram. Output is
  fenced ```` ```mermaid ```` blocks embedded in the index (renders natively on GitHub). If
  diagram generation fails, it is caught and skipped; docs still complete.
- **Output profiles** → `profiles.py`. Three v1 profiles: `readme` (current behavior),
  `api-reference` (per-symbol detail), `onboarding` (getting-started narrative). Prompt-template
  sets keyed by name; adding a 4th later is a one-file change.
- **GitHub Action** → `action.yml` + `cli.py`. Runs in the user's CI on their secret key
  (`ProviderBackend`), generates docs, and opens a **PR** with the changes. This is the viral
  growth loop — one workflow file and a repo documents itself on every PR/merge.

## 6. Reliability & Scale Hardening

The system scales largely **for free because it is distributed**: every developer running stdio
mode executes on their own machine with their own (or host) LLM. The only centralized load is the
Render server, which is kept deliberately thin.

- **Remote server = GitHub convenience only, BYOK-first.** The public Render endpoint does **not**
  spend the operator's LLM key by default (that is an unbounded cost/abuse risk). It uses the
  caller's provider key, or host sampling when available.
- **Fix the credential leak.** `core/repo_loader.py` currently logs the clone URL with the
  embedded token. Mask tokens in all logs.
- **SSRF + abuse guard (remote).** A public server that clones any URL is an SSRF/DoS vector.
  Validate URLs against known git hosts, block private/internal IP ranges, and cap repo size /
  file count / total tokens before work begins.
- **Concurrency control.** A global bounded semaphore + queue so simultaneous requests cannot
  exhaust the host (Render free tier: 512 MB / 0.1 CPU). The per-request
  `ThreadPoolExecutor(max_workers=10)` becomes a bounded, configurable, sensibly-shared pool.
- **Per-file fault isolation + retries.** One file's LLM error never aborts the run. Add timeouts
  and exponential-backoff retry on transient provider/rate-limit errors.
- **Guaranteed temp cleanup.** Per-request `mkdtemp` with cleanup that runs even on crash/timeout
  to avoid disk fill.
- **Re-enable DNS-rebinding protection** with an explicit allowlist (currently disabled in
  `mcp_server_impl.py`).
- **Structured logging + `/health` endpoint** for observability at scale.
- **Housekeeping.** The outer repo currently embeds `ai_document_creator` as an accidental gitlink
  with no `.gitmodules`. Flatten it so CI/packaging is sane.

**Render note:** the free tier (spin-down, 512 MB, 0.1 CPU) is acceptable for a demo but will
choke under real concurrency. The design assumes the operator either moves the remote to a small
paid instance or relies on distributed local/stdio usage for volume. The code is identical either way.

## 7. Decisions

- **Packaging:** pure-Python via `uvx` (no npm wrapper).
- **Push model:** PR-based; never force-push a user's default branch.
- **Default cost model:** remote endpoint is BYOK/host-sampling first; operator key is never the
  silent default.
- **LLM abstraction:** LangChain `init_chat_model("<provider>:<model>")` for provider backends;
  `langchain-ollama` for local models.

## 8. Build Order (each phase independently shippable & tested)

1. **Foundation** — `sources.py` + `backends.py` (multi-provider + sampling) + `config.py`.
   Pipeline works local & GitHub, any LLM. Nothing user-facing breaks.
2. **Hardening** — Section 6 items. Lock it down before promoting.
3. **Incremental + drift** — `cache.py`, `check_doc_drift`.
4. **Profiles**, then **Mermaid diagrams**.
5. **Packaging** (`uvx` + MCP registry) and **GitHub Action**.

## 9. Testing Strategy

- Unit tests per module: sources, backends (with a fake LLM backend), cache hashing, profiles,
  diagram fallback.
- One integration test that runs the whole pipeline against a tiny fixture repo using a mock
  backend (no API calls) — replacing the current `scratch_test_push.py` / `verification_script.py`
  with a real `pytest` suite.
- Target: every module has a test, with a green CI gate required before publishing.

## 10. Non-Goals (later phases)

- Static-site output (MkDocs/Docusaurus).
- Chat-with-codebase.
- Docstring/JSDoc injection into source.
- Hosted multi-tenant accounts / billing.
