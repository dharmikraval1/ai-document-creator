# Phase 5 — Rich Documentation: Design Spec

**Date:** 2026-07-07
**Branch:** claude/mcp-ai-document-tool-19j3v3
**Goal:** Documentation that explains *how the system fits together*, not just
what each file does: Mermaid architecture/dependency diagrams, per-file flow
charts, and selectable output profiles — with zero risk of shipping broken
diagram syntax.

## Features

### 1. Deterministic Mermaid diagrams (`core/diagrams.py`) — no LLM involved

Two diagrams are computed from the file list by static analysis and appended
to the generated `README.md` under `## Architecture Diagrams`:

- **Module dependency graph** (`graph LR`): scans Python
  (`import x` / `from x import`) and JS/TS (`import … from './x'`,
  `require('./x')`) files, keeps only *internal* edges (both ends inside the
  repo), and renders them as a flow chart.
- **Project structure chart** (`graph TD`): directories → files tree.

Robustness rules:
- Node IDs are synthetic (`n0`, `n1`, …); labels are quoted and
  double-quote-escaped, so hostile filenames can't break the diagram or the
  markdown around it.
- Node/edge caps (default 40 nodes / 60 edges, env-overridable via
  `MAX_DIAGRAM_NODES`) with a "+N more" note, so a 5,000-file repo yields a
  readable diagram instead of soup.
- Skips silently (returns None) when there's nothing meaningful to draw
  (< 2 edges / < 2 files).

Because these are generated by code, not by the model, they are always valid
Mermaid — this is the flagship diagram path.

### 2. LLM-drawn per-file flow charts — validated, never trusted

The per-file prompt (in `architecture` and `readme` profiles, when
`diagrams=True`) invites the model to add a `### Diagram` section with a
Mermaid flowchart *only when the file has non-trivial control flow*.

Every generated markdown then passes through `sanitize_mermaid_blocks()`:
each ```mermaid fence must start with a known diagram type
(`graph`, `flowchart`, `sequenceDiagram`, `classDiagram`, `stateDiagram`,
`erDiagram`, `journey`, `pie`) and have balanced brackets; invalid blocks are
downgraded to plain fenced text (content preserved, rendering disabled) so a
hallucinated diagram can never break the page. Applied to per-file docs and
the index alike.

### 3. Output profiles (`core/profiles.py`)

`profile` param (already a `DocConfig` field, previously unused) now selects
the documentation style for both per-file docs and the README:

| Profile | Per-file emphasis | README emphasis |
|---|---|---|
| `readme` (default) | summary, overview, key APIs, usage | classic README: overview, install, usage |
| `api` | signatures, params, returns, errors, examples | grouped API reference index |
| `architecture` | role in system, dependencies, data flow, diagram | components, boundaries, data flow |
| `tutorial` | walkthrough narrative, gotchas | learning path from setup to advanced |

Unknown profile → clear error listing valid names (tool returns error string;
CLI exits with message). Exposed as a tool param on `document_repo` /
`document_local_project` and `--profile` on the CLI; `diagrams: bool = True`
exposed alongside (`--no-diagrams` on the CLI).

## Wiring

- `AgentState` gains optional `profile` / `diagrams` (read with `.get()` —
  old invocations keep working).
- `generate_docs` builds prompts via the profile; `generate_index` builds the
  README via the profile, then **code** (not the model) appends the
  deterministic diagram section, then sanitizes.
- `_run_pipeline` (server) and `run` (CLI) pass both fields; the
  unchanged-files re-index path passes them too.
- Version → **2.2.0**.

## Non-goals

- Rendering diagrams to images (GitHub/MCP hosts render Mermaid natively).
- Call-graph analysis inside files (AST-level) — import-level is the right
  cost/benefit for v1 of diagrams.
- New languages beyond Python/JS/TS for dependency edges (structure chart
  covers everything regardless of language).
